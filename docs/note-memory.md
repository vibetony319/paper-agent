# 笔记记忆与 Agent 注入

本文说明本地笔记检索、上下文预算和 Agent 使用笔记时的安全边界。

## 笔记类型与筛选

后端只有三种 `note_type`：

- `manual`：用户手写。
- `explanation`：选区解释自动生成。
- `translation`：选区翻译自动生成。

模型生成笔记保留 `model_profile_id`、不含密钥的模型快照和 `ai_generated: true`。用户编辑后 `user_edited` 变为真，但 `ai_generated` 保持原值。前端筛选使用“全部 / 我的笔记 / 解释 / 翻译”，不会引入新的持久类型。

## 检索评分

`NoteMemoryService` 只使用本地 SQLite，不要求向量模型。查询与笔记先做词项化：

- 英文、数字和下划线等连续 token，长度至少 2；
- 中文连续片段拆成相邻二元组。

基础分是查询与笔记正文的词项重合数；同一页加 4 分，相邻页加 2 分，选区原文重合加 6 分，手写笔记加 1 分，用户已编辑加 1 分。排序键是 `(-score, -updated_at, note_id)`，因此结果确定。零重合的笔记只在与选区同页时返回，避免所有手写笔记永远进入上下文。

## 上下文预算

默认最多取 8 条笔记、总预算 6,000 字符。超出预算的笔记不会进入 prompt。每条格式为：

```text
[笔记 note:<id> | 类型:用户 | 页码:3]
<note_data>笔记正文</note_data>
```

开头声明这些是“不可信笔记参考”，不能覆盖系统指令，也不能替代论文原文证据。

## 安全边界

- 笔记检索严格限制在请求论文内，不跨论文。
- 注入笔记不等于 Citation Guard 的原文引用；没有论文工具证据时仍返回 `insufficient_evidence`。
- 笔记正文先做 XML 转义，模型无法通过笔记数据逃出数据块语义。
- 选区附件使用 `<selected_text page="N">` 包裹后加入当前模型输入，用户持久正文保持不变。

## 与论文引用的区别

`citation_element_ids` 只表示经过 Citation Guard 校验的论文原文元素；`note_references` 只表示本次请求实际注入的本地笔记。删除笔记后历史仍显示引用标识，`available` 为假，二者不会互相替代。表级引用关系和论文删除语义见[数据模型与删除恢复](data-model.md)。
