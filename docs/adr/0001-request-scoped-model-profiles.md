# ADR 0001：请求作用域模型档案

## 状态

已接受

## 背景

阅读工作区需要在同一会话内切换不同的 OpenAI-compatible vLLM 模型，并让选区解释/翻译、论文助手和知识图谱都使用用户为本次请求选择的模型。启动时创建一个全局模型客户端无法表达这种选择，也无法为历史结果保留稳定来源；同时，本地单用户产品当前只支持 vLLM，不需要抽象多个供应商。已实现边界见[模型服务与模型档案](../model-services.md)，产品与架构约束见[阅读工作区设计](../superpowers/specs/2026-08-21-reading-workspace-annotations-model-profiles-design.md)。

## 决策

- 所有选区辅助、Agent 和图谱请求都显式携带 `model_profile_id`；[ReasoningClientProvider](../../src/paper_agent/services/reasoning_clients.py) 在需要实际调用模型时解析档案，并按 `(profile_id, revision)` 提供该次请求固定使用的 chat、structured 和 tool 客户端；已完成请求的幂等重放直接读取历史结果。
- 聊天框切换模型只影响下一次请求，不重置 `conversation_id`，历史消息顺序和会话身份保持不变。
- 请求开始时生成不可变模型快照，快照只含 `profile_id`、显示名、`base_url`、模型名和修订号。AI 笔记、Agent 消息和图谱运行分别保存该快照，以便档案随后修改时仍可追溯。
- 模型档案删除采用逻辑删除：档案立即停用且从普通列表消失，历史快照继续可读；正在被请求使用的档案由 usage lease 阻止删除。
- 数据库档案的 API 密钥不进入 SQLite、API 响应、模型快照或缓存键，只通过 `secret_ref` 关联到数据目录中的 [ModelSecretStore](../../src/paper_agent/services/model_secrets.py)；[ModelProfileService](../../src/paper_agent/services/model_profiles.py) 在逻辑删除档案时同步删除对应 secret。环境兼容档案的密钥直接来自运行配置，不写入该秘密文件。
- 环境变量配置只在没有启用的数据库档案时暴露为只读兼容档案，调用方仍须显式提交其保留 ID；它不是多模型 UI 的主要配置路径，也不是请求失败后的隐式回退。

## 后果

- 同一会话可以连续使用不同模型，且每条生成结果都能按请求追溯到当时的非敏感配置；档案更新或删除不会改写历史记录。
- 选区辅助、Agent 和图谱实际调用时必须传递显式档案 ID 并获取 usage lease。数据库档案分别要求基础对话、结构化输出加工具调用、结构化输出能力；能力不足或档案不可用时停止。只读环境档案跳过已保存能力的门禁，直接尝试调用并由运行时处理失败；这些路径均不隐式换用默认模型。
- 客户端缓存必须包含修订号并保持有界；一次请求开始后的档案变更不会影响该请求，但下一次请求会解析新修订。
- secret 与元数据分离降低了数据库导出、API 和 Git 泄露密钥的风险，但本地密钥文件仍受运行账户和本机权限边界约束。
- 环境变量部署保持兼容，但只有一个只读档案，不能提供数据库档案的编辑、逻辑删除和多模型管理能力。

## 被否决方案

- **仅在进程启动时创建单例模型客户端**：实现简单，但不能在同一会话内按请求切换模型，也不能可靠保存请求时快照与来源。
- **通用多供应商 Model Gateway**：可统一不同厂商协议，却会在当前仅支持 OpenAI-compatible vLLM 的范围内引入额外路由、鉴权、能力映射和错误语义，超出已实现边界。
