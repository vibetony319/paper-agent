# ADR 0003：可崩溃恢复的论文永久删除

## 状态

已接受

## 背景

论文拥有源 PDF、解析结果、图谱、批注、笔记、会话、消息及引用，SQLite 当前没有以全表级 cascade 统一表达这些所有权。若文件系统与数据库分开直接删除，进程在阶段之间退出可能留下“论文行仍存在但源 PDF 已丢失”或不可追踪的暂存文件。当前表顺序与恢复语义见[数据模型与删除恢复](../data-model.md)，产品与架构约束见[阅读工作区设计](../superpowers/specs/2026-08-21-reading-workspace-annotations-model-profiles-design.md)。

## 决策

- [PaperOperationCoordinator](../../src/paper_agent/services/paper_operations.py) 为每篇论文协调普通操作与删除：有活动写操作或已有删除时返回 busy；删除开始后新的选区辅助、Agent、图谱等论文操作不能进入。当前选择拒绝冲突请求，不主动取消或等待正在运行的生成任务。
- [PaperDeletionService](../../src/paper_agent/services/paper_deletion.py) 先验证源 PDF 位于受管 `papers_dir`，写入 `prepared` marker，再把文件原子移动到同一数据目录的 `.trash` 并写入 `staged` marker。
- 文件暂存完成后，[PaperRepository 的 PAPER_DELETE_ORDER](../../src/paper_agent/storage.py) 在一个数据库事务中按依赖逆序删除消息引用与锚点关联、消息与会话、选区请求、笔记锚点关联与笔记、高亮、锚点矩形与文本锚点、图谱证据与边和节点、文档元素、章节、页面、处理运行，最后删除论文行。
- 数据库提交后 marker 进入 `cleanup_pending`，再删除暂存 PDF 和 marker；应用启动时运行 `recover_pending()`，以论文行是否仍存在决定恢复源文件或完成暂存清理。
- 数据库事务失败时回滚并尝试把 PDF 移回原位置；进程在任一 marker 阶段退出时，由持久 marker 保留恢复依据。
- 论文删除会清理该论文的会话、消息、笔记引用和模型调用记录，但不删除全局模型档案；运行中的模型请求处于论文操作边界内，因此会使删除返回 busy。
- `.trash` 只是内部恢复暂存区，不是用户回收站；请求必须用论文 ID 显式确认，成功后产品语义是永久删除。

## 后果

- 对持久 marker 与文件仍完整的进程崩溃，启动恢复以论文行是否存在为准：提交前恢复暂存 PDF，提交后清理暂存 PDF；marker 的阶段名不替代数据库事实。
- 暂存 PDF 的最终 unlink 失败可以留下 `cleanup_pending` 文件，但不会重新暴露已删除论文。损坏 marker 保留在原处并列入恢复结果的 `damaged_markers`；[create_app](../../src/paper_agent/app.py) 当前调用恢复但未处理该返回报告，不能视为已有自动告警。
- 数据库提交是补偿边界：提交前失败尝试还原 PDF；提交后写入 `cleanup_pending` 失败会保留已有 `staged` marker 与暂存 PDF，不再还原源文件。下次启动依据论文行已不存在完成清理。对应故障注入测试同时覆盖 marker 写入失败、最终 marker 删除失败与重复恢复。
- 删除顺序成为需要随 schema 演进维护和验证的显式契约；新增论文拥有表时必须加入逆序事务，而不能假定外键自动处理。
- 协调器和恢复流程是当前单服务进程、本地文件系统边界，不构成分布式锁或跨主机事务。
- 用户不能从 UI 恢复已确认删除的论文；恢复机制只用于保证系统阶段一致性，不改变永久删除语义。

## 被否决方案

- **把全表 cascade 作为主要删除机制**：现有外键未统一配置 cascade，且历史笔记引用允许无外键的悬空 `note_id`；仅靠外键级联不能覆盖这些清理边界，也不能协调源 PDF 的可恢复删除。
- **先直接 unlink 源 PDF 再提交数据库事务**：数据库失败或进程退出后可能保留可见论文记录，却永久失去源文件。
- **只删除数据库后再尝试删除原路径文件**：提交与文件删除之间缺少持久恢复依据，失败状态无法安全判断应恢复还是清理。
- **向用户提供回收站**：需要保留期限、容量、恢复冲突和额外产品状态；当前确认后的永久删除不包含这些能力，内部 `.trash` 只服务崩溃恢复。
