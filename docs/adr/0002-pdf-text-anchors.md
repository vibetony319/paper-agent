# ADR 0002：PDF 文本锚点

## 状态

已接受

## 背景

批注、高亮、选区解释和原文跳转必须对应浏览器中用户实际选中的文字，并在刷新、缩放或阅读区宽度变化后恢复位置。后端 PyMuPDF 文本块服务于解析和论文证据定位，其分块与几何并不等同于 PDF.js 在浏览器生成的字符 DOM。当前契约见[PDF 文本批注后端契约](../pdf-annotations.md)，产品与架构约束见[阅读工作区设计](../superpowers/specs/2026-08-21-reading-workspace-annotations-model-profiles-design.md)。

## 决策

- 每页的 PDF.js Canvas 与 TextLayer 使用同一个 PDF page 和同一个 viewport，见 [PdfPageView](../../web/src/components/PdfPageView.tsx)；用户选择必须起止于同一页、可复制的 TextLayer。
- 前端从浏览器 `Range.getClientRects()` 取得单页多行矩形，以同页 surface 为基准裁剪并归一化到 `[0, 1]`，保留浏览器返回顺序，过滤空矩形后从 0 连续编号，保存 `{order, x0, y0, x1, y1}`，见[选区采集实现](../../web/src/components/pdfSelection.ts)。这不额外推断多栏文字的语义阅读顺序。
- [锚点模型](../../src/paper_agent/annotations.py)持久化从 1 开始的 `page_number`、选中文字 `quote`、归一化矩形以及可选的同论文 `element_id`，以原文和定位信息保留选区语境；当前浏览器采集不自动填充 `element_id`。邻近段落上下文没有独立持久化字段，[选区辅助实现](../../src/paper_agent/services/selection_assists.py)当前只发送选文和页码。设计规格允许解释附带有预算的同页邻近上下文，但该扩展尚未实现，不能把后端文本块坐标改造成浏览器字符框。
- 展示时把归一化矩形映射到当前 viewport；高亮恢复和来源跳转因此不依赖创建锚点时的像素尺寸、设备像素比或缩放比例。
- 首版只接受单页文本选择，不提供 OCR 或跨页选区合并；扫描件、损坏文字层和不可复制 PDF 不产生文本锚点。

## 后果

- 刷新、缩放、容器宽度变化和页面重新挂载后，可以用当前页面尺寸恢复同一相对位置；持久化数据不绑定某台设备的像素坐标。
- 同页跨行选择会形成多个有序矩形，服务端仍需校验页码、坐标范围、矩形顺序、文本长度和可选元素的论文归属。
- 可选择的 PDF.js TextLayer 成为精确文本批注的前提；没有可用文字层时仍可查看原 PDF，但不能创建这类锚点。
- PDF.js 文字抽取变化可能影响选中文字和矩形，需要通过保存的 quote 与论文元素关联诊断；后端解析坐标仍只承担论文证据定位职责。
- OCR 与跨页选择需要新的文字来源、置信度和多页锚点模型，留在当前版本边界之外。

## 被否决方案

- **从 PyMuPDF 文本块反推浏览器字符框**：服务端块边界、字体布局和浏览器 TextLayer DOM 不是同一几何事实，反推会让选区与用户可见文字错位。
- **持久化 CSS 或设备像素坐标**：像素值随缩放、容器宽度、设备像素比和重新渲染变化，无法稳定恢复或跳转。
- **首版加入 OCR**：需要额外文本识别、坐标对齐和置信度语义，不能复用“可复制 TextLayer 即事实来源”的契约。
- **首版支持跨页连续选区**：需要多页锚点、排序、交互和服务端 schema，增加的复杂度不属于当前已实现单页模型。
