# Paper Reading Workbench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a local React workbench that lets a reader upload and select a paper, read its original PDF, inspect a bounded evidence-backed graph, write source-linked notes, and ask citation-aware questions.

**Architecture:** Add a standalone Vite + React + TypeScript application under `web/`. It talks only to existing relative `/api` routes through a development proxy, so the browser never needs local paths or model configuration. The workspace owns one shared active source target (`element id`, page, normalized bounding box); PDF highlights, graph evidence, notes, and Agent citations all set that target rather than inventing separate navigation states.

**Tech Stack:** React, TypeScript, Vite, PDF.js display layer (`pdfjs-dist`), React Flow (`@xyflow/react`), ELK.js (`elkjs`), Vitest, Testing Library, FastAPI, SQLAlchemy, pytest.

## Global Constraints

- Keep the product local-first, single-user, and vLLM-only. Do not add accounts, cloud storage, embeddings, web retrieval, a provider gateway, or client-side model calls.
- The UI must request only relative `/api` URLs. Vite proxies `/api` to `http://127.0.0.1:8000` during development; no CORS policy or absolute host configuration is added.
- `paper_only` output is rendered only after the existing non-streaming API response has passed Citation Guard. The UI must not synthesize, stream, or label unsupported paper claims as grounded.
- A citation target is a located `document_elements.id` owned by the active paper. Graph node IDs and edge IDs remain navigation aids, never answer citations.
- Every source jump uses the API-provided `page_number` and normalized `bbox`; unlocated elements are never highlighted or assigned a guessed page.
- Keep the graph intentionally bounded: overview mode renders at most 24 nodes and a selected-node view renders the API's one-hop subgraph. Do not render a full unbounded graph as the primary view.
- Use the original PDF endpoint for the reader (`/api/papers/{paper_id}/source`) and PDF.js' display layer. Do not expose an internal source-file path.
- Keep frontend source, tests, package manifests, and `package-lock.json` in Git. Never commit `web/node_modules/` or `web/dist/`.
- Use TypeScript strict mode. Run `tsc --noEmit` separately from Vite because Vite transpiles TypeScript without full type checking.
- Preserve all existing Python API behavior while adding the small paper-list endpoint required by the local sidebar.

def list_papers(self) -> tuple[Paper, ...]:
    with self.engine.connect() as connection:
        rows = connection.execute(
            select(papers).order_by(papers.c.original_filename.asc(), papers.c.id.asc())
        ).mappings().all()
    return tuple(self._paper_from_row(row) for row in rows)

def list_summaries(self) -> tuple[PaperSummary, ...]:
