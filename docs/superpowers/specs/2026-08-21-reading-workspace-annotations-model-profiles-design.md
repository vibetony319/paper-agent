# 论文阅读工作区、批注记忆与多模型配置设计

## 文档状态

- 日期：2026-08-21
- 状态：产品与架构设计已确认，等待实现计划
- 适用仓库：`paper-agent`
- 设计类型：在现有 React、FastAPI、SQLite、PyMuPDF、MarkItDown 与 vLLM 架构上的增量升级

本文是对早期 `2026-08-08-paper-agent-design.md` 的增量设计。早期文档中关于本地优先、证据优先、解析分层、知识图谱和 Citation Guard 的原则继续有效；以下旧假设被本文取代：

1. 阅读页从固定三栏改为以 PDF 为中心的双栏工作区。
2. PDF 阅读器从仅渲染画布升级为画布、文字层、批注层和证据层组合渲染。
3. 单一启动时推理模型改为多个可持久化 vLLM 模型档案，并在每次请求时动态选择。
4. 简单纸张笔记扩展为可关联精确选区、可由模型生成、可被 Agent 检索的笔记记忆。
5. 增加论文及全部关联数据的安全永久删除能力。
6. 产品界面和主要开发文档改为中文优先。

## 1. 背景与目标

当前 Web 工作区已经能够上传论文、查看 PDF 页面、浏览知识图谱、记录简单笔记并进行有引用的论文问答，但仍存在几个直接影响深度阅读的问题：

- PDF 只有画布，没有可选择文字层，无法围绕原文进行解释、高亮和精确笔记。
- 三个固定工作栏平均分配空间，论文正文过窄，长时间阅读时注意力分散。
- 模型在服务启动时固定，不能管理多个 vLLM 服务，也不能在聊天框切换。
- 笔记只是一段附着于页码或文档元素的正文，不能表示精确选区，也不会自动成为 Agent 的长期上下文。
- 缺少论文删除接口，源 PDF 和关联数据无法通过产品安全清理。
- UI 与 README 仍以英文为主，不符合中文用户的日常使用习惯。

本次升级的目标是把现有工作台变成一个面向中文用户、证据可追溯、适合长时间阅读的本地论文阅读环境。用户可以直接选中论文原文，进行高亮、手写笔记、一键解释或翻译，并在后续对话中让 Agent 自动利用这些笔记。

## 2. 已确认的产品边界

### 2.1 本次必须交付

- 桌面端以 PDF 为主的双栏阅读工作区。
- 可复制文字 PDF 的连续滚动、文字选择和精确批注。
- 选区工具栏：`解释`、`翻译`、`记笔记`、`问助手`、`高亮`。
- 解释和翻译在选区附近流式输出，并在成功完成后自动形成笔记。
- 高亮、手写笔记和模型生成笔记持久化，刷新后恢复。
- Agent 自动检索当前论文中的相关笔记，并标明实际使用的笔记。
- 多个 vLLM 模型档案的新增、编辑、停用、删除、默认设置和能力测试。
- 聊天框模型切换；模型切换后继续当前会话。
- 解释、翻译、Agent 对话和知识图谱构建统一使用聊天框当前模型。
- 每次模型调用保留可追溯的模型快照。
- 永久删除 PDF 及其解析数据、图谱、批注、笔记、会话、消息和引用。
- 中文优先 UI、中文 README 与足够其他开发者继续开发的中文技术文档。

### 2.2 首版明确不做

- 扫描版 PDF OCR；没有可用文字层时给出明确中文提示。
- 多用户账号、登录、团队协作和权限隔离。
- 云同步、分享链接和跨设备自动同步。
- OpenAI、Anthropic 等多供应商网关；模型服务仍限定为 OpenAI-compatible vLLM。
- 跨页连续选区；跨页内容需要分两次批注。
- 可编辑知识图谱、协作批注和批注版本历史。
- 回收站式用户恢复；用户确认后的论文删除是永久删除。

### 2.3 部署假设

当前版本是单用户本地部署。论文、模型档案、笔记和会话属于当前应用实例，不引入用户 ID。该假设不允许数据层偷懒：所有新增表仍必须通过 `paper_id` 明确限定作用域，为未来多用户迁移保留边界。

## 3. 设计原则

1. **阅读优先**：PDF 始终是主内容，图谱、笔记和 Agent 是辅助工作台。
2. **证据优先**：论文事实引用原文元素；笔记引用和论文引用在 UI 与数据中分开表示。
3. **当前模型唯一决定本次调用**：界面不再存在互相矛盾的图谱模型、解释模型和聊天模型选择。
4. **模型输出不是原文**：解释、翻译和模型生成笔记必须带 AI 生成标识及模型信息，不能伪装成论文内容。
5. **失败不产生残缺正式数据**：流式结果可以临时展示，但只有完成后才写入正式笔记。
6. **坐标与缩放解耦**：选区和高亮保存归一化 PDF 页坐标，不保存某次渲染的像素位置。
7. **中文优先但不翻译技术标识**：用户文案使用中文，PDF、vLLM、API、JSON 等标准术语保留。
8. **局部升级而非重写**：复用现有解析、图谱、Agent 和 Citation Guard，新增职责通过独立服务接入。

## 4. 方案选择

### 4.1 已选择：在现有架构上增量升级

继续使用：

- React + TypeScript 前端
- FastAPI 后端
- SQLite 持久化
- PyMuPDF + MarkItDown 解析管线
- OpenAI-compatible vLLM 客户端
- 现有知识图谱构建与 Agent Runtime
- 现有 Citation Guard

在此基础上新增 PDF 文字层、文本锚点、批注与笔记记忆、模型档案服务、按请求动态选择的模型客户端，以及论文删除服务。

### 4.2 未选择方案

**前端本地存储批注**开发较快，但不能可靠支持跨浏览器、备份、Agent 笔记检索和关联数据删除，因此不采用。

**重建工作区或事件溯源架构**长期扩展性更强，但会同时替换当前解析、图谱、Agent 和 UI，超出本次目标，因此不采用。

## 5. 整体系统结构

```text
┌──────────────────────────── React Web ────────────────────────────┐
│ 论文库                                                           │
│ 阅读工作区                                                       │
│  ├─ PDF 画布 + TextLayer + AnnotationLayer + EvidenceLayer       │
│  ├─ SelectionToolbar / InlineAssistantPopover                    │
│  ├─ 论文助手 / 知识图谱 / 笔记                                   │
│  └─ 固定聊天框 + 当前模型选择器                                  │
└──────────────────────────────┬────────────────────────────────────┘
                               │ /api
┌────────────────────────── FastAPI ────────────────────────────────┐
│ Paper routes                  Annotation routes                   │
│ Note routes                   Model profile routes                │
│ Agent routes                  Graph routes                        │
│                                                                    │
│ AnnotationService             NoteMemoryService                   │
│ ModelProfileService           ModelSecretStore                    │
│ ReasoningClientProvider       PaperDeletionService                │
│ 现有 Agent / Graph / Citation Guard                               │
└───────────────────────┬──────────────────────┬─────────────────────┘
                        │                      │
                 SQLite + 本地 PDF       多个 vLLM 服务
```

`ReasoningClientProvider` 是本次模型架构的关键边界。Agent 和图谱服务不再持有应用启动时创建的单例客户端，而是在一次业务请求开始时，根据 `model_profile_id` 解析出一个不可变客户端。一次请求开始后，即使模型档案被修改，该请求也继续使用开始时的配置快照。

## 6. 信息架构与阅读界面

### 6.1 论文库

现有永久侧边栏改为独立论文库首页。论文库负责：

- 上传 PDF。
- 显示文件名、处理状态、页数、最近阅读时间。
- 打开阅读工作区。
- 触发论文删除。
- 进入全局模型设置。

阅读页不保留常驻论文列表，以避免挤占 PDF 宽度。顶栏左侧提供返回论文库的入口。

### 6.2 桌面阅读工作区

- 左侧 PDF 区默认约占 62%。
- 右侧工具区默认约占 38%。
- 中间分隔条可拖动，宽度偏好保存在浏览器本地。
- 顶栏仅包含返回、论文标题、处理状态、模型设置和论文菜单。
- 右侧标签页为 `论文助手`、`知识图谱`、`笔记`。
- 聊天框固定在右侧底部，在三个标签页中保持可见。
- 聊天框模型选择器是当前阅读工作区的模型事实来源。

知识图谱从原固定中栏移入右侧标签页。用户查看图谱时，PDF 仍可保持足够宽度；点击图谱证据继续驱动 PDF 定位。

### 6.3 小屏布局

当可用宽度不足以同时保证 PDF 与工具区的最小宽度时，切换为单栏：

- 顶部提供 `论文` 与 `工具` 切换。
- PDF 状态、当前页和选区草稿不能因切换而丢失。
- 选区工具栏优先显示常用动作，空间不足时将次要动作放入更多菜单。

### 6.4 视觉语言

- 暖灰工作区背景、白色 PDF 画布、深墨色正文、单一靛蓝强调色。
- 高亮默认使用低饱和黄色，保持正文对比度。
- 控件采用紧凑矩形；圆角和阴影只用于浮层、菜单和模态框。
- 不使用装饰性渐变、巨型标题、英文全大写标签和无意义卡片嵌套。
- 使用中文系统字体栈；数字、代码和模型标识可使用等宽字体。
- 所有交互状态拥有可见焦点，支持键盘操作并尊重 `prefers-reduced-motion`。

### 6.5 参考界面的取舍

参考图用于确定“左侧论文、右侧工作台、选区附近工具栏、底部聊天框与模型选择器”的交互骨架，不做逐像素复制。首版不额外引入论文总结、论文评价、相关推荐和分享等未确认业务；已有知识图谱与论文助手进入右侧标签页，优先完成选文、笔记和模型能力。

## 7. PDF 渲染、文字选择与定位

### 7.1 页面渲染层

前端通过现有原始 PDF asset API 加载同一份 PDF，使用 PDF.js 为每页组合以下层级：

```text
PageViewport
├─ CanvasLayer       PDF 原始视觉内容
├─ TextLayer         可选择文字，透明覆盖并与画布使用同一 viewport
├─ AnnotationLayer   用户高亮和选区关联标记
└─ EvidenceLayer     图谱证据、Agent 论文引用的临时定位效果
```

TextLayer 与 CanvasLayer 必须使用同一 PDF.js page、viewport、rotation 和 scale，不使用后端文字块猜测浏览器字符位置。后端 `document_elements` 继续负责论文证据定位；用户选区由 PDF.js 文字层产生。

原始 PDF asset API 必须返回正确的 `application/pdf`、文件长度和 byte-range 响应，使 PDF.js 不必为长论文反复下载完整文件。现有页面图片接口继续用于诊断、缩略图或降级展示，不再作为主阅读器文字选择的基础。

页面改为连续纵向滚动。长论文使用虚拟列表，只渲染视口附近页面；卸载页面前保存阅读位置，重新挂载时恢复高亮。缩放、旋转或容器宽度变化后重新计算像素矩形，但不修改持久化坐标。

### 7.2 文本锚点

一个用户选区转换为一个文本锚点，包含：

- 精确引用文本 `quote`。
- 1-based `page_number`。
- 按阅读顺序排列的一个或多个矩形片段。
- 每个矩形以 `{x0, y0, x1, y1}` 归一化到 `[0, 1]`。
- 可选的最近 `document_element_id`，仅在匹配可信时保存。
- PDF 文本层版本和选区文本哈希，用于后续一致性诊断。

首版只接受单页选区，但支持同一页跨行产生多个矩形。空白选区、仅标点选区或跨页选区不会直接保存，并提供中文说明。

服务端验证页码、坐标范围、矩形顺序和文本长度。客户端坐标不直接被信任。

### 7.3 选区工具栏

非空合法选区结束后，在选区附近显示：

`解释｜翻译｜记笔记｜问助手｜高亮`

- `解释`：打开轻量回答浮层，使用当前模型解释选中内容。
- `翻译`：打开相同浮层，将选中内容翻译为中文。
- `记笔记`：打开简短输入框，保存手写笔记并关联文本锚点。
- `问助手`：把引用、页码和锚点作为上下文附件放入聊天框，不自动发送。
- `高亮`：立即保存默认黄色高亮；点击已有高亮可写笔记或删除高亮。

`Esc` 关闭浮层，关闭不等于删除已经持久化的高亮或笔记。

### 7.4 反向定位

以下来源都可以定位 PDF：

- 手写笔记关联的文本锚点。
- 解释或翻译自动生成笔记关联的文本锚点。
- Agent 的论文原文引用。
- Agent 使用的笔记引用。
- 知识图谱节点和边的证据。

定位时先滚动到页面，再等待页面挂载和文字层完成，最后短暂突出对应矩形。论文原文证据使用证据色，笔记锚点使用笔记色，避免两类来源混淆。

## 8. 解释、翻译与笔记记忆

### 8.1 轻量回答浮层

解释和翻译不创建主聊天消息。调用流程为：

```text
合法选区
  → 创建临时请求（当前 model_profile_id）
  → 浮层接收流式 delta
  → 模型完整结束
  → 在一个数据库事务内创建文本锚点与生成笔记
  → 返回“已存入笔记”状态
```

浮层状态包括：`准备中`、`生成中`、`已存入笔记`、`已取消`、`生成失败`。网络中断或用户取消时，已经显示的文本可复制，但不得写入正式笔记。重试复用同一个幂等键，成功结果最多保存一次。

模型生成笔记带有：

- 类型：`explanation` 或 `translation`。
- 生成结果正文。
- 原文锚点。
- 模型档案 ID 和不可变模型快照。
- 生成时间。
- `AI 生成`标记。

模型生成笔记与手写笔记一样允许编辑和删除。编辑后保留来源类型与模型快照，并标记为“用户已编辑”。

翻译请求以精确选文为主；解释请求可以附带同页附近的文档元素和章节标题，但必须清楚分隔选文与邻近上下文，且总长度受预算限制。

### 8.2 笔记面板

笔记面板提供：

- `全部`、`我的笔记`、`解释`、`翻译`筛选。
- 原文摘录、页码、正文、类型和模型信息。
- 编辑、删除、复制和定位原文。
- 明确的空状态和检索失败状态。

笔记默认按创建时间倒序，可在当前论文内搜索。删除高亮不自动删除已经关联的笔记；删除最后一个关联笔记也不自动删除独立高亮，两个动作必须由用户分别确认。

### 8.3 Agent 自动读取笔记

每次 Agent 请求由 `NoteMemoryService` 在当前 `paper_id` 范围内检索笔记，候选信号包括：

- 用户问题与笔记正文的全文相关性。
- 当前附加选区与笔记原文锚点的重合或邻近关系。
- 页码和文档元素关系。
- 最近使用与最近编辑时间。
- 可选语义检索；如果实例配置了可用向量能力，可以加入混合排序，但首版不能强制依赖额外向量模型。

服务按明确的字符或 token 预算选择前若干条笔记，而不是把全部笔记塞入提示词。笔记以不可信参考数据的形式注入，不能覆盖系统指令或触发工具调用。

相关性相近时优先用户手写或用户已编辑的笔记；模型生成笔记始终保留 `AI 生成`来源标签，不能因为被再次检索就获得与论文原文相同的证据等级。

Agent 最终响应分别返回：

- 论文原文引用：继续由 Citation Guard 校验 `document_element_id`。
- 笔记引用：返回 `note_id` 和可选文本锚点，用于说明回答参考了哪些笔记。

笔记不能替代论文证据。`paper_only` 模式中的论文事实仍必须有合法论文原文引用；只有笔记而没有原文证据时，回答必须明确其来源是用户或模型笔记。

## 9. 多模型档案与动态调用

### 9.1 模型档案

一个模型档案包含：

- `id`
- 中文显示名称
- vLLM OpenAI-compatible `base_url`
- vLLM 暴露的 `model_name`
- 可选 API 密钥的后端密钥引用
- `enabled`、`is_default`
- 配置修订号 `revision`
- 最近能力检测结果与时间
- 创建和更新时间

设置页支持新增、编辑、停用、删除、设为默认和连接测试。读取接口从不返回完整 API 密钥，只返回 `has_api_key` 与掩码。日志、异常和 OpenAPI 示例不得包含真实密钥。

普通模型档案只在 SQLite 保存 `secret_ref`。实际密钥由 `ModelSecretStore` 写入 `data_dir/secrets/model-profiles.json`，采用临时文件加原子替换，并尽可能限制为当前操作系统用户可读。该方案的目标是防止密钥通过普通数据库导出、API 或 Git 泄露，不承诺抵抗拥有本机管理员权限的攻击者；README 必须明确这一点。用户清空或删除档案密钥时同步删除对应 secret。

现有环境变量配置继续作为兼容入口。当数据库没有可用档案而环境变量完整时，后端暴露一个只读的“环境变量模型”；它可以使用和测试，但不能从 UI 修改或泄露密钥。用户可以复制其非敏感字段创建普通档案。

### 9.2 能力检测

测试接口独立报告：

1. 基础对话。
2. 严格 JSON Schema 结构化输出。
3. 显式工具调用。

检测结果只描述最近一次测试，不假定服务永久可用。解释、翻译只要求基础对话；知识图谱要求结构化输出；完整 Agent 要求结构化输出和工具调用。调用前检查最近能力状态，但真正请求失败时仍按运行时错误处理。

### 9.3 当前模型选择

聊天框选择器保存稳定的 `model_profile_id`。选择优先级为：

1. 当前论文工作区上次选择且仍可用的档案。
2. 默认模型档案。
3. 第一个启用的模型档案。
4. 无可用模型状态。

当前选择可以保存在浏览器本地作为界面偏好，但任何后端模型调用必须显式携带 `model_profile_id`，不能依赖浏览器状态或隐式全局变量。

当前模型用于：

- 解释选区。
- 翻译选区。
- Agent 消息。
- 核心和深层知识图谱构建。

### 9.4 会话内切换模型

切换模型后继续当前会话，不自动新建会话。下一条用户请求开始使用新模型，历史消息按原顺序提供给新模型；界面在每条助手消息旁显示实际模型名称。

为了可追溯，消息保存模型档案 ID 和请求开始时的快照：显示名称、服务地址的安全表示、模型名称和修订号。API 密钥永不进入快照。用户消息也记录当次请求选择的模型，以便用户消息与助手结果成对审计。

删除模型档案采用逻辑删除：立即删除其 API secret、停用档案并设置 `deleted_at`，普通列表不再返回。它不会删除历史消息、生成笔记或图谱；历史数据继续通过非敏感快照展示。新请求不能选择已删除档案。如果删除的是当前或默认档案，UI 必须先选择回退档案，并给出明确提示。

### 9.5 图谱模型追溯

核心或深层图谱构建请求显式携带当前 `model_profile_id`。每次构建运行保存模型快照。已有图谱不会因聊天模型切换而自动重建；用户主动重建时才用新的当前模型替换相应阶段结果。

## 10. 后端服务边界

### 10.1 `ModelProfileService`

- 验证模型名称、URL、启用状态和默认唯一性。
- 通过 `ModelSecretStore` 管理 API 密钥存取、原子写入与输出脱敏。
- 执行能力检测并保存结果。
- 处理环境变量模型兼容逻辑。

### 10.2 `ReasoningClientProvider`

- 根据档案 ID 和修订号创建不可变 vLLM 客户端。
- 按 `(profile_id, revision)` 做有界缓存。
- 档案修改或删除后使旧缓存失效。
- 为一次请求返回配置快照。
- 不把档案选择逻辑散落到 Agent、图谱和批注路由中。

### 10.3 `AnnotationService`

- 验证并保存文本锚点与矩形。
- 创建、读取和删除高亮。
- 维护锚点与笔记的关联。
- 生成稳定的定位响应。

### 10.4 `NoteMemoryService`

- 统一读取手写和模型生成笔记。
- 在论文范围内执行检索、排序和上下文预算裁剪。
- 返回用于模型上下文的不可执行数据块和用于 UI 的笔记引用。
- 笔记新增、编辑或删除后增量更新可选检索索引。

### 10.5 `PaperDeletionService`

- 获取论文级删除锁，拒绝新的写操作。
- 取消或等待同一论文正在运行的解析、图谱与生成任务。
- 校验源 PDF 位于应用管理目录。
- 执行可崩溃恢复的文件暂存和数据库删除。
- 记录并重试最终物理文件清理。

## 11. 数据模型

### 11.1 新增表

#### `model_profiles`

保存模型档案、`secret_ref`、能力状态、默认状态、修订号和可选 `deleted_at`。API 密钥只进入独立密钥存储，不能出现在普通序列化结果中。

#### `text_anchors`

保存 `paper_id`、引用文本、文本哈希、可选文档元素、创建时间。业务 API 中可以继续称为“批注锚点”。

#### `text_anchor_rects`

保存锚点的页码、矩形顺序和归一化坐标。首版通过约束保证同一锚点只有一个页码。

#### `highlights`

保存锚点、颜色、创建与更新时间。一个锚点最多一个活跃高亮。

#### `note_anchors`

连接现有 `notes` 与文本锚点。使用连接表而不是删除原 `element_id` 和 `page_number`，保证已有笔记兼容。

#### `note_memory_index`（可选实现）

如果使用 SQLite FTS，保存笔记的可检索镜像。它是可重建索引，不是正文事实来源。

### 11.2 现有表扩展

`notes` 增加：

- `note_type`：`manual`、`explanation`、`translation`。
- `model_profile_id`，允许为空。
- `model_snapshot_json`，允许为空。
- `ai_generated`、`user_edited`。
- `created_at`、`updated_at`。

`conversation_messages` 增加：

- `model_profile_id`，允许历史记录为空。
- `model_snapshot_json`。
- 请求幂等键或对应请求 ID。

`processing_runs` 或等价图谱构建运行记录增加：

- `model_profile_id`。
- `model_snapshot_json`。
- 图谱构建幂等键。

新增笔记引用连接表，将助手消息连接到 `note_id`；现有 `conversation_message_citations` 继续只表示论文原文元素。

### 11.3 约束

- 所有锚点、批注、笔记和引用必须与消息或论文具有相同 `paper_id`。
- 所有归一化坐标满足 `0 <= x0 <= x1 <= 1` 与 `0 <= y0 <= y1 <= 1`。
- 未删除的模型档案最多一个默认项。
- 幂等键在业务作用域内唯一。
- 模型快照不包含 API 密钥。
- 数据库迁移必须保留现有笔记、会话和图谱。

## 12. API 设计

最终命名可以在实现计划中与现有路由风格统一，但能力边界固定如下。

### 12.1 模型档案

```text
GET    /api/model-profiles
POST   /api/model-profiles
PATCH  /api/model-profiles/{profile_id}
DELETE /api/model-profiles/{profile_id}
POST   /api/model-profiles/{profile_id}/test
POST   /api/model-profiles/{profile_id}/default
```

删除正在被请求使用的档案返回冲突；停用或逻辑删除不会级联删除历史快照，逻辑删除会清除对应 secret。

### 12.2 文本锚点、高亮与笔记

```text
GET    /api/papers/{paper_id}/annotations
POST   /api/papers/{paper_id}/highlights
DELETE /api/papers/{paper_id}/highlights/{highlight_id}
POST   /api/papers/{paper_id}/selection-assists
POST   /api/papers/{paper_id}/notes
PATCH  /api/papers/{paper_id}/notes/{note_id}
DELETE /api/papers/{paper_id}/notes/{note_id}
```

`selection-assists` 接收选区、`action = explain | translate`、`model_profile_id` 和幂等键。响应使用基于 `fetch` 的 `text/event-stream`，事件至少包括：

- `started`
- `delta`
- `completed`，包含最终保存的笔记
- `error`

只有 `completed` 可以宣告正式笔记已创建。

### 12.3 Agent 与图谱

现有 Agent 请求增加：

- 必填 `model_profile_id`。
- 可选选区上下文。
- 请求幂等键。

响应增加：

- 实际模型快照。
- 使用的笔记引用。
- 继续保留经过 Citation Guard 校验的论文引用。

现有核心和深层图谱构建请求增加 `model_profile_id` 与幂等键。模型能力不足返回稳定错误码，不创建半成品构建记录。

### 12.4 论文删除

```text
DELETE /api/papers/{paper_id}
```

请求要求显式确认字段或一次性确认令牌，避免浏览器误触。成功返回 `204 No Content`；论文不存在返回 `404`；存在无法取消的运行任务返回 `409`；恢复或内部清理失败返回可追踪的 `500`。

## 13. 论文永久删除与崩溃恢复

SQLite 外键当前没有统一级联删除，不能只删除 `papers` 行。本次采用显式服务编排，并通过测试固定删除顺序。

### 13.1 用户体验

删除入口位于论文库和阅读页论文菜单。确认弹窗明确列出：

- 原始 PDF。
- 页面、章节和文档元素。
- 知识图谱及构建状态。
- 高亮、笔记和笔记索引。
- 对话、消息、论文引用和笔记引用。

用户二次确认后永久删除。成功后阅读页立即失效并返回论文库。

### 13.2 文件与数据库流程

```text
1. 获取 paper 删除锁并标记拒绝新写入
2. 验证源文件解析后的真实路径位于 data_dir/papers
3. 在 Windows 文件占用情况下做有界重试，再将源 PDF 原子移动到 data_dir/.trash/<paper-id>-<token>.pdf
4. 写入同目录恢复标记
5. 在单个数据库事务中按外键逆序删除全部关联行和 papers 行
6. 提交成功后删除暂存 PDF 与恢复标记
7. 若最终物理清理失败，进入本地清理队列并在启动时重试
```

数据库提交前失败时回滚事务并把 PDF 移回原位置。进程崩溃后，启动恢复逻辑检查 `.trash`：

- 数据库仍存在论文行：恢复暂存 PDF。
- 数据库已不存在论文行：完成暂存文件清理。

这样不会出现“数据库仍可见但原 PDF 永久丢失”的状态。提交后暂存区可能短暂保留不可访问的待清理文件，但不会作为有效论文数据暴露。

### 13.3 删除顺序

实现应从依赖最深处开始，至少覆盖：

1. 消息的论文引用与笔记引用。
2. 会话消息与会话。
3. 笔记索引、笔记锚点关系和笔记。
4. 高亮、文本锚点矩形和文本锚点。
5. 图谱节点/边证据、图谱边、图谱节点。
6. 文档元素、章节、页面和处理运行。
7. 论文行。

模型档案是全局配置，不随论文删除。

## 14. 错误处理与并发

### 14.1 稳定错误分类

前端按稳定业务码显示中文信息，而不是解析英文异常字符串。至少区分：

- `MODEL_PROFILE_NOT_FOUND`
- `MODEL_PROFILE_DISABLED`
- `MODEL_CAPABILITY_UNAVAILABLE`
- `MODEL_CONNECTION_FAILED`
- `INVALID_TEXT_SELECTION`
- `PAPER_BUSY`
- `PAPER_DELETING`
- `DUPLICATE_REQUEST`
- `INSUFFICIENT_EVIDENCE`
- `DELETE_RECOVERY_REQUIRED`

错误响应可包含安全的调试关联 ID，真实密钥、本地绝对路径和模型原始敏感响应不得返回前端。

### 14.2 流式失败

- 解释或翻译失败：浮层保留临时文本供复制，显示重试，正式笔记不存在。
- Agent 失败：用户消息可以标记失败并重试；未通过 Citation Guard 的模型文本不作为论文回答展示。
- 图谱失败：原有已完成阶段图谱保持不变；新结果通过校验后才替换。

### 14.3 并发规则

- 同一篇论文可以阅读和查询，但永久删除与写操作互斥。
- 同一幂等键只能产生一个正式结果。
- 模型档案修改通过 `revision` 做乐观并发控制。
- 笔记编辑使用更新时间或版本号防止静默覆盖。
- 一次模型请求在开始时冻结档案快照，中途切换聊天框模型不影响正在生成的请求。

## 15. 安全与隐私

- 模型 URL 只接受 HTTP/HTTPS，禁用意外协议和不必要重定向，并设置连接、读取和总生成超时。
- 因本地 vLLM 常位于 `127.0.0.1` 或局域网，不能简单禁止私网地址；设置页必须提示该地址将由后端访问。
- API 密钥只在后端使用，列表与详情接口永不返回明文。
- 日志统一脱敏 `Authorization`、API key、查询参数中的凭证和模型配置。
- PDF 路径通过解析后的绝对路径与应用管理目录比较，拒绝路径穿越和符号链接逃逸。
- PDF 文本、手写笔记和模型生成笔记全部视为不可信数据，作为有边界的参考内容进入提示词。
- 用户上传的原 PDF 字节不可被解析结果或模型输出覆盖。
